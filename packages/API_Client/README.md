# API_Client

TypeScript API client for **Vyzorix** (the audio-scope-view platform).

## Package Contents

- **`src/generated/`** — Generated client code from the Vyzorix OpenAPI spec: the orval `tags-split` axios SDK (`src/generated/<tag>/`), the aggregate wire DTOs (`vyzorixUpdateServerAPI.schemas.ts`), the CUE-derived config types (`src/generated/schema/index.ts`), and the per-shape wire DTOs used by the web app's generated react-query hooks (`src/generated/schemas/`). Do **not** edit these by hand; regenerate them instead (see below).
- **`src/`** — Hand-written wrappers/utilities that build on the generated code (request helpers, domain mappers, errors, etc.).
- **`eslint.config.js`** — ESLint (flat config) for this package.
- **`tsconfig.json` / `tsconfig.dts.json`** — TypeScript configs. `tsc --noEmit` / `tsc --build` are the authoritative type checks.

## Linting & Type-Checking

```bash
# lint the package (flat config, TS parser)
pnpm lint

# type-check the generated client + sources without emitting
pnpm typecheck
```

### ESLint carve-outs
- **`src/generated/**`** — generated orval/CUE output is exempt from `consistent-type-definitions` and `explicit-function-return-type` (type aliases and implicit returns are expected in codegen).
- **`*.test.ts` / `*.spec.ts`** — test files may use `any` and implicit returns.

## Regenerating

The client is generated from the repo-root OpenAPI spec via the root `orval.config.js`
(`sdk` and `vyzorixRQ` targets), then post-processed by `tooling/codegen/organize_query_hooks.py`.
The CUE-derived config types are generated by `tooling/codegen/build_schemas.py` from `tooling/schema/*.cue`.
Regenerated output lives in `src/generated/` — commit it after verifying with typecheck + lint above.
